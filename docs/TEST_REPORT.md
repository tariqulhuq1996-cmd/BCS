## এই Phase-এ ধরা পড়া ও ঠিক করা ত্রুটি

| ত্রুটি | প্রভাব | সমাধান |
|---|---|---|
| একই ধাপ একসঙ্গে দুবার শুরু হলে (যেমন দুবার ক্লিক) দুটি পরীক্ষা তৈরি হতো | শিক্ষার্থী দুটি আলাদা প্রশ্নসেট পেতে পারত | তৈরির পর অসমাপ্ত "যমজ" পরীক্ষা খুঁজে সবচেয়ে আগেরটি রাখা হয়; ৩ বার পরপর পরীক্ষা করে নিশ্চিত |
| হালকা থিমে ধূসর লেখার কনট্রাস্ট ৪.২১:১ | কম দৃষ্টিশক্তির ব্যবহারকারীর পড়তে কষ্ট | রং গাঢ় করে ৪.৮৭:১ (WCAG AA) |
| নিরাপত্তা-হেডার ছিল না | অন্য সাইট ফ্রেমে বসিয়ে প্রতারণা (clickjacking) সম্ভব | X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy; প্রোডাকশনে HSTS |

(আগের Phase-গুলোতে ধরা পড়া ত্রুটি — অপশন-তুলনা, একই-অপশনের প্রশ্নে নম্বর, অ্যাডমিন-মেনু ইত্যাদি — সেখানেই ঠিক করা ও পরীক্ষায় যুক্ত।)

## যা স্বয়ংক্রিয়ভাবে পরীক্ষিত নয়

- **আসল ব্রাউজারে পূর্ণ end-to-end স্বয়ংক্রিয় পরীক্ষা** (Playwright ইত্যাদি) নেই; প্রতিটি Phase-এ হাতে ব্রাউজারে পরীক্ষা করা হয়েছে। প্রয়োজন হলে পরে যুক্ত করা যায়।
- **ইমেইলে পাসওয়ার্ড-রিসেট** — ইমেইল-সেবা এখনও যুক্ত নয় (Phase 10)।
- **একাধিক সার্ভারে চালানো** — লগইনের চেষ্টা-সীমা এখন একটি প্রসেসের মেমোরিতে; একাধিক সার্ভারে Deploy করলে ডেটাবেস-ভিত্তিক করতে হবে (Phase 10)।
- **Content-Security-Policy** — Next.js-এর inline স্ক্রিপ্টের জন্য nonce-ভিত্তিক CSP Deployment-এর সময় ঠিক করা হবে।

## আবার চালানো

```bash
npm run db                         # আলাদা টার্মিনালে

npm run test:load -- --users 300   # লোড-পরীক্ষা (ঐচ্ছিক: --base http://localhost:3100)
npm run check:integrity            # যেকোনো সময়, কিছু লেখে না
```
